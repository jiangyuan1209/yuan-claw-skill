# 接口测试用例设计方法

> `api-auto-test` 技能的补充参考。SKILL.md 覆盖主流程，此处提供更系统的用例设计方法。

## 一、等价类划分

把每个入参的取值域划分为若干等价类，每类取一个代表值：
- **有效等价类**：合法取值（如 amount ∈ [0.01, 999999]，取 100）。
- **无效等价类**：非法取值（负数、0、超大值、非数字、空、null）。

每个有效类尽量合并到一个正常用例；每个无效类单独一个异常用例（便于定位）。

## 二、边界值分析

缺陷常聚集在边界，重点测：
- 数值：`min-1, min, min+1, max-1, max, max+1`。
- 字符串长度：`len=0, 1, min-1, min, max, max+1`（对应 `@Size(min,max)`）。
- 分页：`pageNum=0, 1, 极大值`；`pageSize=0, 1, max, max+1`（防内存溢出）。
- 集合：空集合、单元素、上限元素数。
- 时间：起始/结束边界、开始>结束的非法区间。

## 三、错误注入 / 异常路径清单

- 必填缺失：逐个删除 `@NotNull/@NotBlank` 参数。
- 类型错误：数字位传字符串、日期传非法格式。
- 格式非法：`@Email`/`@Pattern`/手机号/身份证传非法值。
- 枚举越界：传枚举外的值。
- 越权访问：用 A 用户 token 访问 B 用户资源（id 替换）。
- 鉴权缺失/失效：不带 token、带过期 token、带伪造 token。
- 幂等/重复：同一请求重复提交，观察是否重复写库。
- 大字段/超长字符串：验证长度上限与截断。
- 特殊字符：SQL 关键字、`<script>`、emoji、unicode（验证转义与编码）。

## 四、按 HTTP 方法关注点

| 方法 | 关注点 |
|------|--------|
| GET | 查询参数校验、分页、排序、空结果返回结构、越权读 |
| POST | 必填校验、重复提交幂等、返回体 id/资源定位、副作用提示 |
| PUT | 全量更新语义、不存在资源的处理、并发覆盖 |
| PATCH | 部分更新、null 与"不传"的区分 |
| DELETE | 幂等性、删除不存在的资源、级联影响、软删除标记 |

## 五、断言策略

- 不要只断言 HTTP 200，要断言**业务结果**：统一响应体的 `code`/`success`/`message`。
- 关注**空指针类返回**：data 是否该为 null / 空集合，与文档一致。
- 关注**错误码规范**：不同失败原因应返回可区分的错误码，而非笼统 500。
- 关注**响应时间**：为慢查询接口设置 `maxTimeMs` 上限。

## 六、用例命名规范

`<接口>-<场景>-<预期>`，例如：
- `创建订单-金额合法-成功`
- `创建订单-金额为负-校验失败`
- `查询订单-未登录-鉴权失败`
- `分页查询-pageSize超限-返回上限`

## 七、常见坑

- **鉴权头缺失**导致全部 401：先确认 token 获取方式（登录接口/固定测试 token）。
- **context-path 漏拼**：`server.servlet.context-path=/api` 时 baseUrl 或 path 需包含。
- **Content-Type 不匹配**：表单接口用 `application/x-www-form-urlencoded`，body 传字符串 `a=1&b=2`。
- **路径参数编码**：`@PathVariable` 含特殊字符时需 URL 编码。
- **写操作污染数据**：POST/DELETE 会改真实数据，尽量用可回滚的测试数据或独立测试库。
